# incubation —— 待孵化的独立项目构想

**放什么**：**不属于 SwarmDrop 本体**、但值得单独立项的项目构想。每篇带**孵化状态**。

**不放什么**：SwarmDrop 自己的方案调研——那属于 [`research/`](../research/)。

## 为什么和 research/ 分开

两者问的不是同一个问题：

| 目录 | 问的问题 | 判定标准 |
|---|---|---|
| [`research/`](../research/) | 「要不要在 SwarmDrop 里做这件事」 | 技术可行性 + 与现有架构的契合度 |
| `incubation/` | 「要不要单独开一个项目做这件事」 | 市场缺口 + 能力沉淀 + 与本人技能栈的匹配 |

混在一起的坏处很直接：`research/` 的每篇都隐含「落地点是本仓」，`/dev-workflow` 也是按
这个前提去读的。一篇「我想另开一个项目」混进去，只会让人误以为 SwarmDrop 要长出一个
它不该有的子系统。

## 一条从第一篇里学到的规矩

**动笔写方案之前，先花 20 分钟做一轮 GitHub + Exa 搜索。**

agent-sandbox 那篇的构想与否决发生在同一天，中间只隔一次调研——那次调研本该发生在
写第一行之前。附带的第二条：**「没人做」是一个待解释的现象，不是一个结论**，
它和「没人要」在星数上长得一模一样。
