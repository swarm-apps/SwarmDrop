Web 端是运行在浏览器里的 SwarmDrop 传输端。它会启动 WASM P2P 节点，通过 helper 进入网络，
再与已配对设备发送或接收文件。

## 快速开始

<Steps>

<Step>

### 启动节点

打开 [/app](/app)。Web 端会创建或恢复浏览器里的节点身份，然后启动 P2P 节点。

节点身份保存在本机浏览器存储中；已配对设备、收件箱和传输历史保存在 IndexedDB 中，刷新页面后
仍然在。收到的文件本身存在浏览器的 OPFS 里，随时可以从收件箱重新下载。

</Step>

<Step>

### 连接 helper

填入 helper 的 multiaddr 并连接。Web 端需要浏览器可拨号的地址，例如 WebSocket 或
`webrtc-direct`，地址末尾应包含 `/p2p/<PeerId>`。

浏览器不能监听本地 TCP/QUIC socket，也不能直接使用原生 TCP bootstrap 地址，所以跨网络可达性
依赖 helper 暴露的浏览器可访问入口。跨网络传输通常还需要 helper 支持 relay / circuit 地址预留。

</Step>

<Step>

### 配对设备

生成配对邀请，或输入另一台设备提供的分享码。

分享码查找依赖 DHT。Web 端必须先连接具备 DHT 能力的 helper，才能通过分享码解析到对方节点 ID
和可拨号地址。

</Step>

<Step>

### 发送和接收文件

选择已配对设备并添加文件，即可发起发送。接收方看到 Offer 后可以接受或拒绝。

接收成功的文件会先写入浏览器 OPFS，再生成下载链接。**发送**过程中请保持页面打开——刷新会中断
发送，且无法恢复；**接收**被中断（对方离线、页面刷新）后可以在传输活动里点「续传」接着传。

</Step>

</Steps>

## Helper 和自托管

helper 是 Web 端进入 P2P 网络的入口，通常负责：

- 提供 WebSocket 或 `webrtc-direct` 等浏览器可拨号地址。
- 参与 DHT，让分享码可以解析到节点 ID 和地址。
- 在直连不可用时提供 relay / circuit 路径。

公共 helper 适合试用。长期使用或私有部署时，可以参考
[自托管引导节点](/docs/self-host) 部署自己的入口，并确保它暴露浏览器可访问的地址。

helper 不解密文件内容。文件传输仍由配对设备之间的加密会话保护。

## 安全上下文

Web 端依赖浏览器安全 API。推荐使用：

| 来源 | 状态 |
| --- | --- |
| `https://你的域名` | 推荐 |
| `http://localhost` | 本机开发可用 |
| `http://127.0.0.1` | 本机开发可用 |
| `http://192.168.x.x` | 不推荐 |

私有 IP 的普通 HTTP 通常不是安全上下文。浏览器可能禁用 `navigator.storage` 或 `crypto.subtle`，
导致节点启动、密钥操作或接收端保存文件失败。

## 已知限制

- 分享码查找需要先连接具备 DHT 能力的 helper。
- **发送到一半刷新页面，这次发送就中断了**：浏览器不能在你不重新选择文件的情况下再读同一个
  文件，因此未完成的发送无法恢复，需要重新选择文件发一次。接收方向不受影响。
- 待处理的 Offer 不跨刷新。刷新后请让对方重新发起一次。
- Web 端不能监听原生 TCP/QUIC 地址，跨网络可达性依赖 helper。
- 接收端文件落盘依赖 OPFS。浏览器存储权限或配额不足时，接收可能失败。
- 传输历史保留最近 100 条已结束的会话；未完成的接收会话保留 7 天。
