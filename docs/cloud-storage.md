# 桌面云存储账户

Google Drive 接收目的地需要用户自己的 Google OAuth 桌面客户端。SwarmDrop 不分发
默认 Client ID 或 Client Secret；账户授权与文件内容不会同步到其他配对设备。

## 创建 Google 客户端

1. 在 [Google Cloud Console](https://console.cloud.google.com/) 创建或选择自己的项目，
   启用 Google Drive API。
2. 在 Google Auth Platform 配置应用名称与受众。处于 Testing 状态时把使用的 Google
   账户加入 Test users；带 Drive 权限的测试授权刷新凭证通常七天到期。
3. 创建类型为 **Desktop app** 的 OAuth client，取得 Client ID 与 Client Secret。
   桌面客户端用本机回环临时端口接收回调，不需要填写网站回调地址。
4. 在 SwarmDrop 设置中的「云存储账户」填写两项，可选填一个便于识别的账户名称。
   点击「连接 Google Drive」，在系统浏览器选择账户并同意授权。
5. 回到应用确认账户状态为「已连接」。可以连接多个 Google 账户。

首期请求 `drive.file`：只访问由该 OAuth 应用创建或用户授予访问的文件。
SwarmDrop 不会自动扩大到整个云盘权限。Google 授权页与 API 必须可达；在需要代理的
网络中，请同时确保系统浏览器和应用进程的网络路径可访问 Google。

## 凭证与重连

凭证位于应用本机数据目录的 `cloud-accounts/google-drive/`，每个账户一份 JSON。
Linux / macOS 文件权限为 0600；凭证是本机明文文件，同用户下的其他进程仍能读取。
token 不进入日志、传输历史、配对同步或前端事件。

正常情况下重启后自动使用刷新凭证。Google 撤销或到期、以及未来轮换 provider 在
远端刷新与本机落盘之间发生崩溃，都可能要求重新连接。点击账户旁的「重新连接」即可
复用已保存客户端配置。持久化失败时账户暂停云操作，应用不会继续使用已作废旧凭证。

「断开」会删除本机凭证并尽力撤销云端授权。若云端撤销失败，应用会如实提示；可再到
Google 账户的第三方连接页面移除授权。断开账户不会删除已经上传的文件。

Google Auth Platform 切换到 In production 可以解除测试状态特有的到期限制；公开分发
客户端是否需要验证，取决于 Google 当时的权限与发布规则。

参考：[Google 桌面 OAuth](https://developers.google.com/identity/protocols/oauth2/native-app)、
[Drive 权限范围](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)。

## 接收到云盘

接收确认弹窗可以选择本地文件夹或已连接的 Google Drive 账户。没有可用账户时，先从
弹窗进入设置完成连接。首期桌面支持云接收，Web 与移动端会明确拒绝云目的地。

P2P 数据仍逐块通过 bao 校验并写入本机暂存，完整文件随后上传。云对象默认放在
`SwarmDrop/<完整接收设备 ID>/<相对路径>`。同路径同根哈希的重复接收可以复用对象，
每次接收仍有自己的记录；同名不同内容添加后缀，不覆盖已有文件。

应用分别显示 P2P 接收进度和当前文件的云上传进度。远端确认完成、对象位置写入本机
数据库之后才显示文件完成并删除暂存。云请求失败会保留暂存；也可以选择「放弃并删除
暂存」。恢复传输时，完整暂存
只重试云发布，不重拉 P2P 分块。恢复仍使用既有会话协商，需对端可达。

上传会话 URI 与确认偏移保存在本机 `cloud-uploads/`，macOS/Linux 权限 0600，原子替换
并同步。重启时核对暂存根哈希并向 Drive 查询确认偏移；上传会话过期会重建云会话。
每条上传使用最多 8 MiB 的显式分块缓冲，最多两条并发上传；这不等于进程内存峰值，
HTTP/TLS、P2P 队列及宿主有额外开销。暂存磁盘需要容纳尚未发布的完整文件。

取消发生在发布期间时，应用先等待当前文件发布与记账收敛，再处理会话取消，避免产生
无完成记录的远端文件。已成功发布的远端文件保留；未完成暂存和上传检查点随取消清理。
进程强制结束后，持久化检查点用于恢复，不把不确定的上传结果当作完成。

收件箱和历史保留云对象的账户、对象 ID 与接收时的显示路径快照。打开前检查对象可访问性，再交给
系统浏览器；重命名或移动后的对象仍按 ID 查询。删除接收记录和断开账户都不会删除
远端文件；云对象没有本地预览、文件夹定位或本地导出操作。

## 加密与权限

设备间传输通过加密的 P2P 通道，接收暂存是已验签的明文。落云阶段用 HTTPS，上传后的
Drive 文件也是明文，由 Drive 的访问控制决定谁能读取。云接收不提供云端内容加密，
不能把 P2P 的端到端加密延伸解释为云盘文件加密。

`appProperties` 属于 OAuth 客户端私有属性。更换客户端会改变能检索的私有属性和
`drive.file` 授权边界，不能依赖旧客户端创建文件的可见性；连接新客户端时应创建新账户
授权。本机历史仍保留旧对象身份，应用不会扩大权限去找回不可见对象。

## 实现与探针记录

账户凭证由 `crates/cloud-auth` 管理；云发布由原生 `crates/storage-cloud` 承担。
`CloudPublisher` 只收本机暂存和发布意图、返回中立对象引用；Drive 的 HTTP 类型与
resumable URI 留在实现内部。`host`、`transfer`、`entity` 不依赖云 HTTP 客户端。

2026-10-01 的真实 BYO `drive.file` 探针已确认目录创建、私有属性写入与检索、对象 ID
查询、17 MiB 的三段 resumable 上传、同接收记录重试及同路径同根哈希复用。
一次新上传包含建目录、校验与初始化共 10.29 秒，平均约 1.73 MB/s；分块上传末帧约
3 MB/s。探针不是 issue #132 的 P2P 吞吐基线，未记录进程内存/磁盘峰值。
浏览器实际打开、第二个 OAuth client、两台设备隔离、断网/进程重启/会话过期和完成响应
丢失仍需手动验收，不能据一次上传成功认定这些场景已通过。

未来接阿里云盘时，复用中立目的地、对象引用、暂存生命周期与账户租约；provider 内部
实现上传初始化、确认进度、完成对账、对象打开与恢复检查点。阿里云盘的 refresh token
轮换、分片签名 URL、upload_id/part 列表与能力差异各自保留，不能用 Drive 的会话 URI
或私有属性约定包装成通用协议。消费级阿里云盘与阿里云 PDS 是不同接口，接入前分别
确认开放平台权限、授权政策、签名有效期、分片约束、秒传与幂等语义。
