# Tasks — background-download-durability

## 1. 先定位真因（不写实现代码）

- [ ] 1.1 真机复现：节点**运行中**（前台服务票在）时开始下载 APK → 切后台 → 等 30s →
      回前台。记录进度是否推进过（`adb logcat` 看下载线程 + 进度回调）
- [ ] 1.2 同上，但**从任务卡片上划杀掉**应用 → 重开 → 观察是否从 0 开始
- [ ] 1.3 节点**未运行**时下载（无前台服务票）→ 切后台 → 观察进程是否被回收
- [ ] 1.4 确认 expo 的 `downloadAsync` 在 app 进入后台后**下载任务本身**是否继续
      （文档只说进度回调不触发，没说任务停止 —— 这两件事必须分开验证）
- [ ] 1.5 把结论写进 `design.md`：假设 A / B / C 各自成立与否，以及用户实际踩的是哪一条

## 2. 方案决策（依赖任务 1）
