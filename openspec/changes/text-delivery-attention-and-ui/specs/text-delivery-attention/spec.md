## Purpose

为已持久化的文本投递提供事件驱动且尊重隐私的到达注意力，使用户无需依赖收件箱轮询也能及时、安全地处理需要确认或已接收的文本。

## ADDED Requirements

### Requirement: 文本投递发布可关联的注意力事件

系统 SHALL 在文本投递完成持久化并进入可由用户处理或查看的状态后，发布携带稳定投递标识、来源设备快照和到达状态的注意力事件。事件 SHALL NOT 包含文本正文；同一投递与到达状态的重复投递不得产生重复的用户注意力。

#### Scenario: 需要确认的文本到达

- **WHEN** 接收策略要求用户确认的文本投递完成持久化
- **THEN** 系统 MUST 发布标记为“需要确认”的注意力事件
- **AND** 事件 MUST 能关联到唯一的待确认投递

#### Scenario: 自动接收的文本到达

- **WHEN** 自动接收的文本投递完成持久化并可在收件箱查看
- **THEN** 系统 MUST 发布标记为“已接收”的注意力事件
- **AND** 事件 MUST NOT 暴露文本正文

#### Scenario: 同一事件被重复交付

- **WHEN** 接收端因重连或同步重复观察到同一投递的同一到达状态
- **THEN** 用户 SHALL 最多看到一次对应的即时注意力提示
- **AND** 收件箱仍 SHALL 保持该投递可访问

### Requirement: 前台以一致的确认和非阻断反馈处理文本到达

当应用处于前台时，桌面、移动和 Web SHALL 使用同一语义区分文本到达：需要确认的投递展示单一的确认面板；自动接收的投递仅提供非阻断反馈并刷新可查看的收件箱状态。确认面板 SHALL 不得因为连续事件而堆叠。

#### Scenario: 前台收到需要确认的文本

- **WHEN** 前台应用收到“需要确认”的文本注意力事件
- **THEN** 系统 MUST 展示一个文本专用确认面板，且用户能够接受或拒绝该投递
- **AND** 同一时刻 SHALL 至多展示一个确认面板

#### Scenario: 前台自动接收文本

- **WHEN** 前台应用收到“已接收”的文本注意力事件
- **THEN** 系统 MUST 刷新或失效对应的收件箱读取状态
- **AND** 系统 MUST 提供非阻断的到达反馈
- **AND** 系统 MUST NOT 展示需要用户决定的确认面板

#### Scenario: 连续到达多个待确认文本

- **WHEN** 已有文本确认面板可见时另一条需要确认的文本到达
- **THEN** 系统 SHALL 保留后到文本为待处理状态
- **AND** 用户完成当前决定后 SHALL 能继续处理下一条待确认文本

### Requirement: 后台通知遵循宿主能力与正文隐私约束

桌面应用在窗口未聚焦时 SHALL 对新文本投递使用系统原生通知。Web 应用仅在用户已明确授权、页面仍存活且页面不可见或未聚焦时 SHALL 使用浏览器通知；不具备这些条件时 SHALL 降级为应用内状态。所有后台通知默认 SHALL 仅显示来源与“收到一条文本”的泛化信息，不得显示文本正文，并且激活通知后 SHALL 导向应用内收件箱。

#### Scenario: 未聚焦的桌面窗口收到文本

- **WHEN** 桌面应用窗口未聚焦且收到文本注意力事件
- **THEN** 系统 MUST 发送一条原生系统通知
- **AND** 通知内容 MUST NOT 包含文本正文

#### Scenario: 已授权且隐藏的 Web 页面收到文本

- **WHEN** Web 页面仍在运行、通知权限已授权且页面隐藏或未聚焦时收到文本注意力事件
- **THEN** 系统 MUST 发送一条浏览器通知
- **AND** 激活该通知 MUST 打开或聚焦应用内收件箱

#### Scenario: Web 权限未授权或页面无法运行

- **WHEN** Web 通知权限未授权、被拒绝、API 不可用或页面已关闭时文本到达
- **THEN** 系统 MUST NOT 反复请求权限或承诺离线通知
- **AND** 文本 SHALL 在下次可用的应用内收件箱读取中可见

### Requirement: Web 通知权限由用户主动管理

Web 应用 SHALL 提供清晰的通知设置入口，并且仅能在用户直接操作该入口时请求浏览器通知权限。系统 SHALL 显示当前授权或不可用状态，并允许用户在未授权时继续使用文本投递。

#### Scenario: 用户主动开启 Web 文本通知

- **WHEN** 用户直接操作“开启文本通知”的设置控件且浏览器支持通知 API
- **THEN** 系统 MUST 发起一次浏览器权限请求
- **AND** 系统 MUST 根据浏览器结果展示已授权、已拒绝或未决定状态

#### Scenario: 浏览器通知不可用

- **WHEN** 当前浏览器或运行环境不支持通知 API
- **THEN** 系统 MUST 展示不可用状态
- **AND** 文本发送、接收和收件箱功能 MUST 保持可用
