## ADDED Requirements

### Requirement: 已接收文件可直接发送到另一台设备

用户 MUST 能从收件箱选中一个或多个已接收文件，直接发起到另一台已配对设备的传输，无需经由系统分享面板、无需先把文件导出到别处。

#### Scenario: 从收件箱详情转发单个文件

- **WHEN** 用户在收件箱详情中对一个已接收文件触发「发送到设备」
- **THEN** 进入选设备界面，该文件已在待发送列表中
- **AND** 选定一台在线的已配对设备后传输正常开始

#### Scenario: 多选转发

- **WHEN** 用户在收件箱中选中多个已接收文件并触发发送
- **THEN** 全部选中文件进入同一次发送的待发送列表
- **AND** 各文件的名称与相对路径与其在收件箱中的呈现一致

#### Scenario: 转发无需系统分享面板

- **WHEN** 用户完成一次从收件箱发起的转发
- **THEN** 全程未唤起系统分享面板
- **AND** 未在设备上产生该文件的额外副本

### Requirement: 转发复用既有的文件已定反向流

从收件箱发起的发送 MUST 复用既有的「文件已定 → 挑设备」反向流，与系统分享入口、「重新发送」共用同一条路径。MUST NOT 为此引入新的传输概念、新的会话类型或新的 IPC 契约。

#### Scenario: 与系统分享入口走同一选设备界面

- **WHEN** 用户分别从系统分享与收件箱发起发送
- **THEN** 两者进入同一个选设备界面
- **AND** 两者的发送行为与进度呈现一致

#### Scenario: 离开选设备界面时清空在途来源

- **WHEN** 用户在选设备界面返回而未发送
- **THEN** 在途来源被清空
- **AND** 下次进入交互式发送页时不会带入这些文件

### Requirement: 文件源标识直接复用接收落盘位置

转发时的文件源标识 MUST 直接使用该文件已落盘的位置，MUST NOT 复制文件、MUST NOT 引入新的文件源类型。

#### Scenario: 移动端复用落盘 URI 作为源

- **WHEN** 用户转发一个已接收文件
- **THEN** 发送侧以该文件的落盘 URI 作为源读取数据
- **AND** `file://` 与 `content://` 两种形态均可直接读取

#### Scenario: Web 端从 OPFS 注册文件源

- **WHEN** 用户在 Web 端转发一个已接收文件
- **THEN** 系统从该文件的 OPFS 句柄取得文件对象并注册为文件源
- **AND** 读取分块的实现与用户经文件选择器选中的文件完全一致

### Requirement: 缺失的文件不得进入发送选择

已被标记为缺失、或在发起时已不在原位置的文件 MUST NOT 进入待发送列表。系统 MUST 在发起前而非传输中途暴露该情况。

#### Scenario: 已标记缺失的文件不可选

- **WHEN** 收件箱中某个文件已被标记为缺失
- **THEN** 该文件的发送动作不可用

#### Scenario: 发起时发现文件已被外部删除

- **WHEN** 用户对一个文件触发发送
- **AND** 该文件已被用户在系统文件管理器中删除
- **THEN** 系统提示该文件已不在原位置并将其标记为缺失
- **AND** 不进入选设备界面，也不开始任何传输

### Requirement: 转发入口不进入常驻导航

从收件箱发起的转发 MUST 是文件上下文中的动作，MUST NOT 在常驻导航中新增入口，MUST NOT 改变「发送从设备开始」这条主路径。

#### Scenario: 常驻导航项不变

- **WHEN** 本能力上线后用户查看常驻导航
- **THEN** 导航项与此前保持一致
- **AND** 未新增「转发」之类的顶层入口

#### Scenario: 发送主路径不变

- **WHEN** 用户从设备卡片触发发送
- **THEN** 进入发送流程时目标设备已选定
- **AND** 该路径的行为未因本能力发生变化
