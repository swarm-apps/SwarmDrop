## Why

SwarmDrop 已能安全地跨网络交付文件，但用户在设备间传递验证码、链接、命令和短说明时，仍需把文本保存成文件或借助第三方服务。这是高频、小而即时的任务；应以同样的端到端加密和已配对设备边界，提供明确、可控的纯文本交付。

本变更把“从剪贴板粘贴后发送”做成一项三端一致的显式操作，而不是难以解释且受系统权限限制的持续剪贴板同步。

## What Changes

- 新增面向已配对在线设备的纯文本交付能力：发送端输入或在用户点击后粘贴 UTF-8 文本，接收端在成功持久化后放入 Drop Inbox，并向发送端返回真实送达结果。
- 新增收发对称的文本投递账本：发送端保留可重试的 Outbox/最近发送记录，接收端保留同一投递的 Inbox 条目；两者不混用收件箱语义。
- 新增独立的轻量文本消息协议和文本载荷；文本不得伪装为 `.txt` 文件，也不得进入文件扫描、分块、断点续传或文件会话恢复链路。
- 复用已配对校验、暂停接收和设备接收策略；策略要求确认时展示文本专用的确认界面，策略拒绝或超限时不得落盘或写入剪贴板。
- 在桌面、移动和 Web 的既有“选定设备后发送”流程内加入“文件 / 文本”内容模式。文本模式提供显式粘贴、编辑、字节上限、发送结果和接收后复制；三端共享同一信息层级、状态和文案语义。
- **BREAKING**：引入新的文本交付 wire、文本投递账本与收件箱文本数据模型，不为旧 wire、旧持久化模型或旧客户端保留兼容分支；旧客户端不声明该能力，不能参与文本交付。
- 明确不实现后台监听、自动读取或自动写入系统剪贴板、连续同步、聊天线程、富文本/图片剪贴板及离线排队。

## Capabilities

### New Capabilities

- `text-delivery`: 在已配对设备间安全协商、确认、持久化和回执纯文本投递。
- `text-delivery-journal`: 持久化收发两侧的文本投递状态、正文与用户发起的幂等重试。
- `text-send-experience`: 定义三端在既有设备定向发送流程中的文本编辑、粘贴、发送与结果体验。

### Modified Capabilities

- `drop-inbox`: 让收件箱能够保存、查看、复制和删除无文件会话依赖的文本内容。
- `inbox-store-port`: 为文本载荷扩展共享收件箱持久化端口及各端一致的读取语义。
- `inbox-item-presentation`: 为文本条目定义可本地化的列表与详情展示派生规则。
- `clipboard-native-access`: 约束桌面文本发送和接收复制继续仅经原生剪贴板封装，并且只由明确用户操作触发。

## Impact

- 影响 `crates/net` 的应用协议、已配对设备能力协商和接收策略接入；影响 `crates/transfer`、`crates/entity`、SQL 与 Web 的文本投递账本和收件箱实现，以及共享 core / UniFFI 暴露的收件箱、Outbox 与发送 API。
- 影响桌面 Tauri、React Native 和 Web/WASM 的发送页、收件箱详情、通知/反馈、可访问性与中英文文案；桌面剪贴板能力继续使用既有原生 plugin。
- 不新增云服务、账号、第三方传输服务或后台同步依赖。
