## 1. 共享文本投递模型与持久化端口

- [ ] 1.1 在 `crates/entity` 定义文本投递方向、状态、稳定投递标识和安全失败类别；删除假定 Inbox 详情必含文件数组的旧 DTO 形态。
- [ ] 1.2 在 `crates/transfer` 定义 `TextDeliveryRecord`、正文校验（非空、合法 UTF-8、最大 64 KiB）、摘要派生和可重试状态转换，并为状态机写单元测试。
- [ ] 1.3 新增 `TextDeliveryStore` 端口，覆盖创建发送记录、读取/列出目标相关 Outbox、原子更新状态、幂等写入接收记录、删除正文和恢复中断状态；调用方不得直接访问具体存储。
- [ ] 1.4 将 `InboxItemDetail` 收敛为文件/文本联合内容，并让接收文本条目经 `delivery_id` 读取正文；保留文件 Inbox 的完整行为。
- [ ] 1.5 为原生 SQL 实现 `text_deliveries` 与接收 Inbox 引用的 schema、唯一约束和原子写入/删除；按本 change 的破坏性策略移除旧 DTO/存储兼容路径。
- [ ] 1.6 为 Web IndexedDB 实现等价的文本投递账本、Inbox 引用、Outbox 查询、事务语义与删除清理，且不从旧记录回填。
- [ ] 1.7 扩展移动共享 core 的端口组装与 UniFFI record/enum 映射，使移动端能读取文本 Inbox 与 Outbox；保持穷尽映射作为 drift guard。

## 2. P2P 文本投递协议与策略接入

- [ ] 2.1 在 `crates/transfer` 定义版本化 `TEXT_DELIVERY` typed RPC、请求/响应编码和安全错误映射，并经 core 协议路由注册；不改用文件控制或数据协议。
- [ ] 2.2 实现发送服务：网络调用前持久化发送记录，使用既有 Endpoint、已配对身份与调用超时，随后原子更新等待确认、送达、拒绝或可重试状态。
- [ ] 2.3 实现接收服务：先校验来源 peer、正文、暂停状态和接收策略；自动接收时持久化，需确认时放入有界、五分钟 TTL 的内存待确认队列。
- [ ] 2.4 接入文本专用的接收确认/拒绝命令与事件，使接受动作先完成接收端文本和 Inbox 的原子持久化再回复发送方。
- [ ] 2.5 实现以 `delivery_id`、来源 peer 和正文绑定的幂等规则：同内容重试返回原送达结果，不同来源或正文的重用明确拒绝。
- [ ] 2.6 在节点启动恢复中把 `sending`、`waiting_confirmation` 等 in-flight 发送记录转为“中断、可重试”，并确保没有自动网络重试。
- [ ] 2.7 补齐协议和策略集成测试：未配对、blocked、暂停、relay 限制、大小限制、自动接收、人工确认、拒绝、过期、持久化失败及回执丢失后的幂等重试。
